# Changelog

All notable changes. Versions follow semantic versioning. Any change to the values generated for a given seed is listed under **Generation changes**, and happens only in a minor release ([stability policy](docs/STABILITY.md)).

## Unreleased

Everything since the last tag (v0.2.0). Work is grouped by theme, not by
version: a release is cut when it is worth one, not per theme.

### Cases that never return

#### Added
- Watchdog (RL10, ADR-0017): when a case runs longer than `hangTimeout`
  (off by default; set `PROPTEST_HANG_TIMEOUT`, e.g. in CI), a thread
  reports the property, what was running, the case's choices and the replay
  command, saves the case in the failure database, appends a `"status":
  "hung"` line to the JSON report, and ends the process with exit code 1.
  The next run replays the case first and prints its inputs (or the
  stateful steps). Needs `--threads:on`, Nim 2's default.

#### Changed
- Saved failures and explicit examples are replayed with their inputs
  recorded (they are few), so the watchdog can print them.

### Generation changes, together

One batch of everything that changes the values generated for a seed, so
that old seeds stop replaying once (docs/STABILITY.md).

#### Added
- `sized(proc(n: int): Gen[T] = ...)` and `g.resize(n)` (C5): generators
  that depend on the current size, or with a fixed size. The size is
  recorded with the case, so shrinking and replay see it.
- `uniqueSeqs(g, ...)` (distinct values; repeats are drawn again, then the
  case is discarded like with `filter`) and `sortedSeqs(g, ...)` (C6).
- Targeted exploration (D4, ADR-0016): `target(score, name)` in a property
  or a state machine. After half of the cases, every other case extends the
  best case so far. The best score per name is in the report and in the
  JSON report (`targets`). The breaker's backoff cap of `b_find` is found on
  20 of 100 seeds instead of 3.

#### Changed
- Faster generation, mostly in debug builds: a case of `x in int` from
  1.13 to 0.70 µs in debug, now within its target; an `int` from 230 to
  100 ns in debug. The library's hot path runs without stack traces and
  runtime checks (its indices are checked by hand), and choice buffers
  grow on demand instead of taking 64 KB per property.
- Performance targets recalibrated (SPEC, section 16): an `int` < 30 ns in
  release and < 150 ns in debug; one choice < 50 ns in debug.
- The "gave up" message also names `uniqueSeqs`.

#### Fixed
- `classify`, `cover`, `label` and `target` used inside a template were not
  rewritten (they arrived as bound symbols), and `stateMachine` rejected a
  command named like an existing proc (`reset`) when generated by a template.

#### Generation changes
- **Signed integers are one choice**, in zigzag order (0, 1, -1, 2, -2, ...)
  instead of a sign and a magnitude. Every property with signed integers
  generates other values for the same seed, and shrinks along another path
  to the same kind of minimum (closest to zero, positive before negative).
  Shrinking the reference bugs takes 644 executions in total instead of 685.
- **Sizes grow with discarded cases too**: a property that discards small
  inputs (`assume(xs.len > 30)`) now reaches larger ones instead of giving
  up. Properties without discards are unaffected by this change.
- **Fewer PRNG calls per integer**: the sign and narrow magnitudes come
  from bits already drawn. Values for a seed change for every integer.
- Saved failures (`.proptest/db/`) from before this batch replay other
  inputs: they pass and are forgotten after three runs, and a real bug is
  found again. Seeds printed by earlier versions do not replay.

### Trust over time

#### Added
- Stability policy (`docs/STABILITY.md`, ADR-0015): within a minor version
  the same seed gives the same values, exploration, stateful sequences and
  counterexample; generation changes only in minor releases, under
  "Generation changes". Says what is not covered (text report, warnings,
  time-dependent behavior) and what to do when upgrading.
- Golden snapshot of the whole pipeline (`tests/t_golden.nim`): 51
  properties (every type and combinator, derived types, mined constants,
  edge bias, sizes, a state machine, shrinking, the failure database file),
  checked on every CI job. `nimble golden` rewrites it for an intended
  generation change.

### Learning it alone

#### Added
- Configuration reference (`docs/CONFIGURATION.md`): recipes for local
  runs, CI, nightly runs, replaying and slow properties; every setting with
  its default, environment variable, cost and when to change it; build
  options and their effect on failure locations; what a replay needs.
- Troubleshooting guide (`docs/TROUBLESHOOTING.md`): from the message you
  see (gave up, flaky, warnings, a seed that does not replay, compile
  errors) to its cause and fix, with real reports.
- A compile-time warning when a build cannot locate failures (A8): without
  stack and line traces (`-d:release`, `-d:danger`), failures other than
  `check` are told apart by exception type only, so two bugs of the same
  type are reported as one. `-d:proptestTraceWarning=false` silences it.
- `scripts/check_docs.nim`, run by `nimble trace` in CI: fails when a
  setting, environment variable or define is missing from the reference, or
  when a link points to a heading that does not exist.

### Your platform and test runner

New API only: the values generated for a given seed are unchanged (checked
against the shrink and detection baselines).

#### Added
- JSON report for CI tools: `PROPTEST_REPORT=<file>` (or the `report`
  setting) appends one JSON line per property, with its status, seed, replay
  command, counts, duration, statistics, warnings and every failure
  (signature, message, inputs, stateful steps). Versioned by `format` (1).
- `unittest2` support (I2), tested in CI: `forAll` and `checkStateMachine`
  work inside its `test` as inside `std/unittest`, with no extra import.
- CI on macOS and Windows, and on Nim devel as an allowed failure (Q2).

#### Fixed
- A memory leak when generating `Table` and `OrderedTable` under ARC/ORC
  when a later draw raised (a Nim 2.2.4 ARC bug; found by LeakSanitizer).

### Your own types, and bugs that stay found

Useful on everyday Nim code: your own types with no generator code, and bugs
that stay found (ADR-0013, ADR-0014). New API only: the values generated by
existing generators for a given seed are unchanged (checked against the
shrink and detection baselines).

#### Added
- Derived generators: `forAll(x in T)` for any object (private fields
  included, from any module), case object, `distinct` type and `ref` object,
  with no code. Recursive types are bounded by `maxDepth` (default 5). A
  user `arbitrary` overload still wins. Unsupported fields, and range
  discriminants (a Nim 2.2.4 limit), are clear compile errors.
- Generators for `Table`, `OrderedTable`, `HashSet`; combinators `tables`,
  `hashSets`, `frequency`, `recursive`; alphabets `alphanumeric`,
  `identifiers`, `unicodeStrings` (valid UTF-8, every plane).
- Failure database: reproduced failures are saved in `.proptest/db/` and
  replayed before any random case on the next runs; forgotten after three
  passing runs; versioned format, atomic writes, entries that no longer fit
  are dropped (`PROPTEST_DB=off` disables it).
- Explicit examples: `forAll(x in int, example(0), example(-1)): ...` run
  first, are not shrunk, and report their inputs.
- `showCode` for objects, `distinct`, `ref`, tables and sets; reports escape
  invisible characters in strings (controls, C1 controls, invalid UTF-8).
- Writing generators guide (`docs/GENERATORS.md`, `examples/generators.nim`);
  compile-time benchmark `b_compile` (PF9).

#### Fixed
- Constant mining could crash the compiler on a non-integer constant
  (`Letters`), and broke files with no integer literal.
- `example(...)` did not compile when the body used `classify`, `cover` or
  `label`: the macros rewrote the body in place, so the example's copy
  referred to another procedure's parameter. The rewrites now build a new
  tree. The failure database key, too, is now computed from the code as
  written instead of the rewritten body, whose generated names changed with
  unrelated code.
#### Generation changes
- Boundary hints no longer include the internal slot numbers (2, 3, ...)
  that the label rewrite left in the body. Only properties and state
  machines with three or more `classify`/`cover`/`label` calls generate
  different values for the same seed; the shrink and detection baselines
  do not use labels and are unchanged.

### Find more bugs, and show what was tested

Find more bugs, and show what was tested (ADR-0012). Every change below was
measured with the new bug-finding benchmark (`benchmarks/b_find.nim`, 100
seeds): a bug at an exact boundary inside a range went from 1 to 68 seeds,
a bug that needs a command to stay away from 3 to 97, with no row worse.

#### Added
- `classify`, `cover` and `label` inside `forAll` and `stateMachine`
  commands; percentages in the report. `cover` fails a property (status
  `psInsufficientCoverage`) only when the share is confidently below the
  requirement (95% Wilson interval); otherwise it warns. Static labels do
  not allocate per case.
- State machines report, without any code, how often each command ran, how
  often its precondition blocked it, and sequence lengths; a command that
  never ran is a warning.
- Boundary hints: `ints(lo, hi, near = [...])`, and integer constants mined
  from the property and from the test file (`mineConstants`, on).
- Swarm testing for state machines (`swarm`, on): half of the sequences
  leave some commands out.
- `edgeBias` setting; edge cases now also cover empty and single-element
  collections, with one shared probability.
- `deadline` (per case, off by default; `PROPTEST_DEADLINE`), `timeBudget`
  (`PROPTEST_TIME_BUDGET`) and `shrinkTimeBudget`.
- Health checks with fixes: data too large for `maxChoices`, input spaces
  smaller than `cases`, generation dominating the run time (`suppress`).
- Verbosity levels (`verbosity`, `PROPTEST_VERBOSITY`): passing properties
  print their statistics and warnings at `normal`; `verbose` prints every
  case, `debug` every shrink step.
- `PropertyResult.firstFailureAt`; reports say at which case a property
  failed.
- Bug-finding benchmark and gate (`b_find`), property patterns cookbook
  (`docs/PATTERNS.md`, `examples/patterns.nim`).

#### Fixed
- CI: the sanitizer jobs could hang forever on `AddressSanitizer:DEADLYSIGNAL`
  (kernel address randomization vs. the ASan of older gcc); they now run one
  suite per job, with timeouts, and a kernel setting that avoids it.

#### Changed
- A new shrink pass lowers a choice and raises the next one, so `-1`
  shrinks to `1` when `0` is not a counterexample.
- `StateRunner` takes a `swarm` parameter.

#### Generation changes
- The exploration distribution changed (edge share, collection edges, hint
  and swarm choices): values generated for a given seed differ from v0.2.
  The golden test was updated with this entry.

## v0.2 (2026-11-20)

### Added
- Stateful (model-based) testing, ADR-0011: the `stateMachine` macro (model,
  setup, teardown, commands with preconditions, `run`, postconditions and
  updates, invariants), `checkStateMachine`, `stateMachineResult`, and the
  `maxSteps` setting. Commands are chosen among those enabled by their
  preconditions, so generated and shrunk sequences are always valid.
- Failing sequences are reported as a `replayCommands` block of Nim code, with
  the failing step; `replayCommands` runs it as a regression test. `showCode`
  prints values as Nim literals (overload it for custom types).
- Shrinking deletes whole collection elements and stateful steps (spans) in a
  new first pass, `deleteSpans`.
- Stateful testing tutorial (`docs/STATEFUL.md`) and `examples/stateful.nim`.

### Changed
- `Probe` (shrinker callback) takes a third parameter, the recorded spans.
- `check` messages print each expression on one line.

### Fixed
- A replayed stateful sequence that raised leaked memory under ARC/ORC
  (found by LeakSanitizer before release).

## v0.1 (unreleased, superseded by v0.2)

### Added
- Design documentation: specification, roadmap, architecture and ADRs 0001–0010.
- MIT license and package manifest (`proptest.nimble`).
- Core library (v0.1): own PRNG and stable hash; choice sequences
  with reused buffers; type-inferred generators for integers, floats, `bool`,
  `char`, `string`, enums, `seq`, `array`, `set`, `Option` and tuples;
  combinators; integrated shrinking with failure signatures, multiple failures
  and flaky detection; `forAll(x in source)` with `check` rewriting and
  `std/unittest` integration; seed replay and crash breadcrumbs.
- `forAllResult`: same arguments as `forAll`, returns the `PropertyResult`.
- Exploration continues after the first failure to find other distinct bugs
  (stops at `maxFailures`); a merge pass in the shrinker (`[1, 1]` → `[2]`).
- Test suite (72 tests, value tests, golden tests), benchmarks, deterministic
  gates (`nimble gate`), traceability check (`nimble trace`), CI workflows.
- `examples/quickstart.nim`.

### Generation changes
- The exploration distribution of integers now proposes the type limits with
  probability 2/16 and avoids 64-bit divisions. Values generated for a given
  seed differ from earlier development builds (no release was affected).

### Fixed (during development, before any release)
- `drawInt` with a single-value range (`lo == hi`) could return values outside
  the range in release builds: `countLeadingZeroBits(0)` is undefined
  behavior. Regression test in `tests/t_choices.nim`.
